# Project context: Interaction Studio (MCP) Logger

Chrome MV3 extension, version 0.2.0 live in the Chrome Web Store (2026-11-06); 0.3.0 (Tools page) packaged in dist/, not yet uploaded.
Logs and decodes events sent to Marketing Cloud Personalization (Evergage, `evergage.min.js`) and the Data Cloud Web SDK (`c360a.min.js`), and offers SDK Tools to swap or edit the SDK on chosen sites.
User-facing docs: `readme.md`. Store listing notes: `docs/chrome-web-store.md`.

## Layout
- `manifest.json`: MV3, service worker `js/background.js`, content scripts `js/sdk-config.js` + `js/contentScript.js` (top frame, `document_start`).
- `js/background.js`: webRequest capture of SDK event requests into `chrome.storage.local`; SDK Tools messages (`MCP_SAVE_SETTINGS`, `MCP_INJECT_LOCAL_SDK`, `MCP_INJECT_MISSING_SDK`, `MCP_STOP_SDK_TOOLS`, `MCP_PAGE_DIAG`, ...).
- `js/sdk-config.js`: shared by the service worker, settings page, content script and Node tests. Settings shape (`__mcp_settings__`), SDK URL regexes (`SDK_SCRIPT_REGEXES`, `isSdkScriptUrl`), DNR session rule builders.
- `js/contentScript.js`: asks the background for the page's SDK Tools status, injects the SDK when the page has none, writes console notes and page diagnostics.
- `popup.*`, `fullscreen.*` (Event Explorer), `settings.*` (SDK Tools), `tools.*` (Tools), `feedback.*`.
- `js/einstein.js` (`McpEinstein`, feedback #1002): Einstein Web Recommendations (igodigital collect.js). `collectInfo` (`/c2/<org>/<endpoint>?payload=` on `*.collect.igodigital.com`, or first-party hosts for the known endpoints), `recsInfo` (`<org>.recs.igodigital.com/a/v2/<org>/<page>/recommend.(js|json)`), payload decode, action names, `emailFields`, `snapshotEtmc` (runs in the page MAIN world: the background reads `window._etmc` after each collect request and stores it as `entry.etmc`), `sdkLabel`/`sdkShort` (IS, DC, EWR). Events store `sdk: "einstein"`; site key `<site> | Einstein Recs (org: <MID>)`.
- `js/decode.js` (`McpDecode.decodePayload`): pasted beacon URL, form body, base64 / URL-encoded / base64url or JSON. Used by the popup and Tools (feedback #1001).
- `js/page-tools.js` (`McpPageTools`, also imported by the service worker): URL checks, `buildOpenSdkRules`, `sameSite`, SDK cookie names, and `collectSdkInfo` (runs in the page through executeScript, so it must stay self-contained).
- `js/theme.js` + `css/theme.css`: System / Light / Dark switch on every page (`[data-theme-switch]` placeholder). Choice in extension `localStorage` (`mcp-theme`), set as `data-theme` on `<html>` before first paint; dark tokens apply for system-dark unless `data-theme="light"`, or for `data-theme="dark"`. Pages sync via the `storage` event; `mcp-themechange` lets the Ace editor follow.
- `tests/`: `npm test` (Node unit tests), `npm run test:smoke` (Puppeteer, extension UI), `npm run test:e2e-sdk` (Puppeteer, SDK Tools on fake sites and CDN via `--host-resolver-rules`; needs local port binding).
- `package.sh` builds `dist/interaction-studio-mcp-logger-v<version>.zip`.

## SDK Tools design
- Modes: Off, Redirect (replacement URL), Edit (edited copy). One at a time. Applies only to `sites` (subdomains included, `*` = all).
- Pages that load the SDK: DNR session rules, scoped by `initiatorDomains`.
  - Redirect: redirect SDK script requests to the URL (priority 50); an allow rule (60) for the URL itself prevents loops. Non-localhost http URLs are fetched on save and served as a `data:` URL.
  - Edit: `data:` URL redirect when under ~1.4 MB; larger copies block the SDK (100) and `injectLocalSdk` evals the code at `document_start`.
  - While a mode is on, the page `Content-Security-Policy` header is removed on the listed sites.
- Pages that do not load the SDK (`injectWhenMissing`, default on, modelled on the Salesforce Interactions SDK Launcher's Inject SDK): at DOMContentLoaded the content script checks script tags and resource timing; if no SDK, `injectMissingSdk` adds the tab to a per-tab block rule (fixed ids 91040+, `condition.tabIds`, priority 55) and injects in the MAIN world (script tag for a direct URL, eval for edited or fetched code). The tab leaves the block list on its next main-frame request or when closed; settings changes clear it.
- Console notes and per-load reports (`__mcp_diag__`) go to Feedback.

## Tools page (user, 2026-11-13; feedback #1001)
- Messages, accepted only from extension pages (`sender.url` is the extension's): `MCP_OPEN_WITH_SDK`, `MCP_SDK_INFO`, `MCP_LIST_COOKIES`, `MCP_CLEAR_SITE_DATA` (`scope` sdk or all, `reload`).
- Inject SDK & open page: the tab is created at about:blank, registered in `chrome.storage.session` `__mcp_open_sdk__` ({ tabId: { src, host } }), rules built, then navigated. Rules per tab: allow 91100+i, CSP strip 91200+i, one block per SDK regex 91300+i*regexes+j (a single joined regex is over Chrome's 2 KB compiled limit); priorities 65 block, 70 allow. They are separate from SDK Tools' so settings changes leave them alone. Each is scoped to the tab and to the site it was opened on (`initiatorDomains` / `requestDomains`, host without www, subdomains included), so another site loaded in the tab keeps its own SDK even before the async cleanup removes the rules (that race failed the E2E intermittently before 2026-11-13). The content script's `MCP_INJECT_LOCAL_SDK` answers `mode: "open-sdk"` for a registered tab on the same site and the background injects the script tag at document_start (`runSdkInPage`, shared with injectMissingSdk). Leaving the site or closing the tab drops the entry.
- SDK info: discovered at run time (Salesforce docs return 403 to automated fetches, and the SDK differs by version). Only zero-argument get/is/has functions are called; names starting Recommend, Campaign, Fetch, Load, Request, Send, Track, Remote, Server after the prefix are listed only. `getAnonymousId` and `getConsents` are the documented ones (Identity Management; Personalization Web Integration).
- SDK cookies: `_evga_` (Personalization) and `_sfid_` (Data Cloud). `cookies` permission added for this (no install warning with `<all_urls>`).
- Tests: `tests/page-tools.test.mjs` (unit), `tests/tools-e2e.mjs` (real Chrome, 16 checks; `npm run test:e2e-tools`, outside the sandbox).
- Checked live 2026-11-13 with the real Data Cloud Web SDK (Training Site connector in the CloudKettle Data Cloud sandbox, `c360a.min.js`) injected into example.com: SDK info shows getAnonymousId, getConsents, getCookieDomain, getCurrentSitemapKey, getLoggingLevel, getSitemapConfig, getSitemapResult, getState, plus 17 properties and 33 other functions; the cookie is `_sfid_30bb` (JSON with anonymousId and consents); Clear SDK cookies gives a new anonymous id; 8 events captured.
- Checked live 2026-11-13 with the real Personalization SDK (`cdn.evgnet.com/beacon/partnercloudkettleca/engage/scripts/evergage.min.js`, the only dataset in the mathes SFMC business unit). The dataset has no sitemap, so the check calls `SalesforceInteractions.init({ cookieDomain })` and one `sendEvent` from the page. SDK info reads both `SalesforceInteractions` (getAnonymousId, getConsents, getCookieDomain, getLoggingLevel, getSitemapConfig, getSitemapResult) and `Evergage` (getConsents, getConfig with account and dataset). This SDK sets both `_evga_<x>` and `_sfid_<x>` cookies; Clear SDK cookies removes both and gives a new anonymous id; injection persists after the reload; events captured.
- An unpacked extension loaded with `--load-extension` gets disabled ("unsupported developer extension") if reloaded with `chrome.runtime.reload()`; restart the browser instead.
